# Singleton

- `JsonUtil` class documentation and implementation describe a “default singleton” instance exposed
  via `getInstance()` and caution about mutating shared singletons

# Factory

- `PieceSupplierStrategy` enum encapsulates a “factory” per strategy to build
  `Supplier<TetrominoType>` instances, storing it in a `factory` field and using it in `create`
  methods.

The following table summarizes how the listed design patterns manifest in this project and where to
find representative implementations.

| Pattern                | Where it Appears                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
|------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Facade                 | `AppContext`: Centralizes navigation, configuration persistence, and audio control so controllers interact with a single simplified surface instead of the underlying subsystems, which is the defining role of a Facade.<br/>`Game` orchestrates the core game state, clock, view, and optional AI, presenting a simple API (tick, apply) to the rest of the app.<br/>`AudioService` exposes high-level toggles for music/SFX and hides the JavaFX media plumbing, giving controllers a simplified façade over the audio subsystem. |
| Observer               | `GameState` defines a `Listener` interface with callbacks like `onClearLines` and `onGameOver` that are invoked when lines are cleared or the game ends.<br/>This allows the UI or services to observe state changes.<br/>`GameClock` – Similarly, `GameClock` exposes a `Listener` with an `onLevelUp` method that observers can register to receive level‑up notifications.                                                                                                                                                        |
| Command                | `GameIntent` is an enum of high-level input actions (`MOVE_LEFT`, `HARD_DROP`, etc.) that encapsulate user commands independent of physical keys.                                                                                                                                                                                                                                                                                                                                                                                    |
| State                  | `GameState` – This class owns the mutable playfield (`Board`), the active `Tetromino`, the upcoming piece queue, and scoring/streak counters.<br/>Its methods apply inputs and transition between states (e.g., locking pieces, clearing lines, updating score).<br/>`GameClock` – Maintains elapsed time, computes continuous and integer levels and gravity intervals, and notifies listeners when the level increases.<br/>Both classes encapsulate evolving state, fitting the State pattern.                                    |
| Decorator              | `ResizableCanvas` – This class wraps a JavaFX `Canvas` inside a `Region`, binds the canvas’s size to the region, maintains a `dirty` flag, and provides a `markDirty` method.<br/>It adds resizing/dirty‑tracking behaviour while exposing the same drawing surface, matching the Decorator pattern. `BoardCanvas` and `NextCanvas` – These classes extend `ResizableCanvas`, inherit its dirty‑flag behaviour and add domain‑specific rendering for the board and next‑piece preview.                                               |
| Abstraction-Occurrence | `TetrominoType` defines the abstract shape and colour of each tetromino and caches rotation‑derived data; `Tetromino` is an immutable record representing a particular tetromino instance with a type, position and rotation.<br/>Methods like `withPosition` and `withRotation` return new instances, separating the concept (type) from its occurrences, which reflects the Abstraction‑Occurrence pattern.                                                                                                                        |
| General Hierarchy      | `ConfigurationService` – This abstract class specifies the contract and synchronisation requirements for loading, saving and caching configuration objects.<br/>`JsonConfigurationService` – A concrete subclass that implements `loadInternal` and `saveInternal` to persist configuration to a `config.json` file.<br/>This hierarchy exemplifies a general template with a specialised subclass.                                                                                                                                  |
| Flyweight              | `TetrominoType` – A static `ConcurrentHashMap` (`CACHE`) stores rotation‑specific derived data (a list of rotated coordinates and bounding box) so that repeated lookups reuse shared objects instead of recomputing shapes. This is a classic Flyweight implementation.                                                                                                                                                                                                                                                             |
| Composite              | `GameView` – Extends `SplitPane` and composes HUD labels plus two custom canvases (`BoardCanvas` and `NextCanvas`).<br/>It maintains a local dirty flag and coordinates repainting of its children via `render`.<br/>This shows a view composed of simpler components.<br/>`GameService` – registers multiple Game instances and advances them with a shared timer; that service plays the role of a composite controller.                                                                                                           |
